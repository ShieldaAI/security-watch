# Security Watch agent practices and implementation plan

**4 November 2026.** Keep Security Watch a scheduled advisory monitor with an optional model analyst. Its strongest design choice is that ordinary code matches packages, chooses recipients and sends messages. A model can interpret a difficult news story, but its classification can still make a noncritical finding quiet. The first changes should limit the data sent for analysis and make those quiet decisions reviewable.

A normal scan loads the operator's inventory, fetches enabled sources, normalizes evidence and applies package or product rules. Optional analysis uses the configured model and, for selected findings, a verifier. The application commits findings and notification jobs together. A separate delivery path checks current policy before an authorized send to a configured Slack or SMTP route. A `start` worker delivers continuously. Fixture dry runs permit an offline rehearsal. The current architecture gives the model no general tool loop. **Independent incident recall, 5 November 2026.** Steps 3 and 5 now measure timely observation and intended immediate routing against an independently enumerated list of urgent deployment incidents. **Retained pilot decision evaluation, 5 November 2026.** Steps 3 and 5 now support independent analyst review of a complete, bounded cohort from a private backup. The score exposes sample sizes, unresolved cases and abstentions. Measuring population recall still requires an independent incident denominator, and production acceptance still requires real analysts, representative pre-agreed sampling and sign-off. ## Two findings that change the order of work

**The candidate expands outbound model data.** A local probe loaded a synthetic inventory through `loadInventory`, selected a matching versioned component in `ModelAnalyzer.analyze`, and injected a memory-only HTTP transport at the OpenAI request builder. A fictional API key satisfied the provider interface. The serialized `input.system.components[0]` included `source_url`, `remediation_evidence[0].reference` and `remediation_evidence[0].recorded_by`, all three supplied canaries. An internal repository path, ticket reference or operator identity could therefore be disclosed **when a model is enabled and that component is selected**. This probe made zero external requests. The extra fields belong to the uncommitted schema and no real disclosure was observed. The public baseline also merits an explicit field contract to prevent future schema growth from widening access. [Loader](../src/inventory.ts) · [Analyzer](../src/models.ts) · [Provider payload](../src/providers.ts)

The released OpenAI Responses adapter requests `store: false` and the Anthropic adapter puts the instruction in a system field and the serialized context in a user message. These protocol settings leave the application responsible for every included field and for checking the provider’s retention terms. cve.now and OSV also receive inventory identifiers through separate lookup paths. Document and configure those disclosures independently. [Provider request formats](../src/providers.ts) · [Disclosure inventory](../SECURITY.md)

**A quiet result can be wrong even with a valid quotation.** A second offline probe passed a noncritical, non-exploited news finding with a configured synthetic channel to `decide`. With `review_before_news_suppression: true`, completed `known_vulnerability_update / not_affected` went to `digest` while `general_news / not_applicable` went to `record`. The flag defaults to `false`. This changes news visibility. Deterministic package applicability and configured critical/exploitation protections have separate rules. Historical real-article testing recorded **9 completed, 7 conflicts and 3 rejections out of 19 target/event pairs**. Those are output dispositions. Ten source-derived synthetic cases still carry `pending_human_review` labels. Neither experiment establishes how many real urgent findings the bot would quietly miss. [Routing](../src/assessment.ts) · [Review switch](../src/config.ts) · [Historical evaluation](quality-review.md)

**Audit validation.** On Node 26.12.0, 71 focused offline cases passed against the local build, with zero skips. The set covered model input/output security, news routing, evaluation scoring, recent advisory fixtures, local inventory evidence and Python version comparisons. Reproduce with `node --test test/{models-security,news-routing,model-evaluation,inventory-evidence-fields,agent-security-hardening,recent-agent-advisories,python-version}.test.mjs` after building the local tree. Historical full-suite numbers and live checks are dated separately in the release review.

## Research and learning path

1. Read Anthropic's distinction between fixed workflows and autonomous agents, then draw the Watch scan as a sequence of code-owned decisions. OpenAI's agent learning track provides a course-style introduction to structured output, human review and tracing. The exercise is to identify the one model decision that can currently silence a story. [Anthropic, Building effective agents](https://www.anthropic.com/research/building-effective-agents) · [OpenAI, Building agents](https://developers.openai.com/tracks/building-agents)
2. Study indirect injection in retrieved content and design input/output contracts around what a bad article could cause. OpenAI's safety guidance emphasizes constrained data flow, approvals and layered controls. Apply it to field projection and news routing in steps 1 and 2. [Greshake et al., indirect prompt injection](https://arxiv.org/abs/2302.12173) · [OpenAI, Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety)
3. Learn to grade the final state, use realistic cases and calibrate automated scoring against human judgment. Implement step 3 locally and keep fixtures portable across providers. The Discernment lessons in Claude Academy’s _AI Fluency_ course prepare analysts to grade the same ambiguous advisory independently and explain which evidence changed the verdict. [Anthropic, Demystifying evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) · [OpenAI, Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) · [Claude Academy, AI Fluency](https://academy.claude.com/courses/ai-fluency-framework-foundations)
4. Use the interchange specifications to resolve concrete evidence gaps. OSV defines affected packages/range events and withdrawal. CycloneDX represents components and relationships. The candidate importer accepts 1.4–1.6 JSON even though the overview also documents 1.7. OpenVEX defines product-specific status and justification for a supplier assertion. [OSV schema](https://ossf.github.io/osv-schema/) · [CycloneDX specification](https://cyclonedx.org/specification/overview/) · [OpenVEX specification](https://github.com/openvex/spec/blob/main/OPENVEX-SPEC.md)
5. For prioritization, keep CISA's observed exploitation, FIRST's severity and forward-looking exploitation forecasts, and local deployment evidence as distinct inputs. CERT/CC shows how an operator can combine these in a decision instead of treating the largest score as an incident. Select any new signal by measured impact on routing. [CISA KEV source](https://github.com/cisagov/kev-data) · [FIRST CVSS v4](https://www.first.org/cvss/v4.0/specification-document) · [FIRST EPSS FAQ](https://www.first.org/epss/faq) · [CERT/CC SSVC](https://certcc.github.io/SSVC/howto/using_epss/epss_probability/)
